Local Training
Each client trains on its private Dirichlet non-IID data shard with attack injection support

1.1 — Data Partitioning (Dirichlet Non-IID)
CIFAR-10 is split across 10 clients using Dirichlet distribution (α = 1.0). Each client holds a heterogeneous subset with imbalanced class frequencies, simulating real-world federated scenarios. A lower α produces more extreme non-IID splits.

1.2 — Global Model Broadcast to Client
Server broadcasts current global model state dict (parameters + BatchNorm buffers) to each client. Client performs a deep copy — no mutation of global model occurs. Model is set to eval() during copy, train() before local SGD begins.
Deep CopyCIFAR10CNNBN Safe
1.3 — Local SGD Training (3 Epochs per Round)
Nesterov SGD with cosine LR annealing: starts at 0.01, decays toward ~0% over NUM_ROUNDS (50). Weight decay L2 regularisation λ=1e-4. Gradient clipping at clip_norm=5.0 prevents exploding updates. 64-sample mini-batches.
cosine_lr = LR * 0.5 * (1 + cos(π * round / NUM_ROUNDS)) floor at LR * 0.01 (never goes to zero)
SGD+NesterovCosine LRGradClip=5.0L2 λ=1e-4Batch=64
1.4 — Attack Injection (Byzantine / Data Poisoning)
AttackManager injects adversarial behaviour on 3/10 clients:
• Byzantine Model Poisoning: Δ_poisoned = −scale × Δ_local (scale=10.0). Reverses and amplifies the gradient.
• Data Poisoning (Label Flip): 50% of training labels randomly flipped before local SGD, corrupting gradient directions on targeted classes without touching the model weights directly.

Update tensor computed via get_state_dict_flat() so BatchNorm running_mean/var buffers are included in the delta — fixing the original BN-buffer-exclusion bug. Flat tensor = concatenation of all parameter diffs.

Phase 2 • pqc.py → PostQuantumCrypto
Post-Quantum Key Exchange (ML-KEM-768 + ML-DSA-65 Setup)
Quantum-resistant key encapsulation using NIST-standardised Kyber-768 lattice cryptography + Dilithium-3 signatures
▾
🔑 ML-KEM-768 Key Exchange Flow
1
Server Generates ML-KEM-768 Keypair
Calls generate_kem_keypair() via liboqs. Produces pk (1184 B) and sk (2400 B). pk is broadcast to all clients. Based on Module Learning With Errors (MLWE) hard problem.
2
Client Encapsulates a Per-Round Session Key
encapsulate(server_pk) → (ct, ss). ct = 1088-byte KEM ciphertext. ss = raw 32-byte shared secret. Client keeps ss, sends ct to server. Session key is fresh every round — forward secrecy.
3
Server Decapsulates → Same ss
decapsulate(ct) with sk → same 32-byte ss. Both sides share a secret without ever transmitting it. IND-CCA2 secure. Immune to Shor’s algorithm (quantum computers cannot factor lattice problems).
4
HKDF-SHA256 Key Derivation (NIST SP 800-227 §7)
Raw ss passed through _derive_aes_key(ss, info="FL-ML-KEM-AES256GCM") using HKDF-SHA256. Prevents biased KEM output from being used directly. Produces a proper 256-bit AES key.
ss_raw (32 B) → HKDF-SHA256 salt=zero(32), info="FL-ML-KEM-AES256GCM" → aes_key = 32 bytes (AES-256)
✏ ML-DSA-65 Digital Signature Setup
1
Client Generates ML-DSA-65 Keypair on Init
Each FLClient.__init__ calls pqc.generate_sig_keypair() producing Dilithium-3 keypair: dsa_pk (1952 B) + dsa_sk (4032 B). Public key is pre-registered with server.
2
Build Bound Message (Anti-Replay)
Canonical signed payload = client_id(4B) ‖ round_num(4B) ‖ ct_kem ‖ nonce ‖ ciphertext. Binding all metadata prevents replay, reorder, and impersonation attacks. Changing any field invalidates the tag.
3
Sign → ML-DSA Signature (2420 B)
sig.sign(bound_msg) produces 2420-byte lattice-based signature. Quantum-resistant: no ECC or RSA — immune to Shor’s algorithm. Based on Module Learning With Errors (MLWE) and Module Short Integer Solution (MSIS).
4
AAD Construction for AES-GCM
AAD = client_id(4B) ‖ round_num(4B) is bound into the GCM authentication tag. Swapping ciphertext to a different round or client context fails tag verification, providing a second layer of anti-replay protection.
Signature payload = client_id(4B) ‖ round_num(4B) ‖ kem_ct ‖ nonce(12B) ‖ enc_update sig = ML-DSA-65.Sign(dsa_sk, payload)

4.1 — ML-DSA-65 Signature Verification
Server reconstructs the canonical bound message and calls pqc.verify(msg, sig, client_pk). If verification fails → update is REJECTED. Prevents impersonation (attacker cannot forge a valid Dilithium signature without dsa_sk) and replay attacks (round_num is in the bound message).

4.2 — ML-KEM Decapsulation → Shared Secret
Server calls decapsulate(kem_ciphertext) with its KEM secret key → recovers the same raw ss the client derived. ss is then passed through HKDF-SHA256 to produce the matching AES-256 key. Forward secrecy: each round uses a fresh ephemeral session key.

⚙ Per-Round Call Ordering (federated_learning.py)
1. weights = trust_mgr.get_weights(valid_ids, round_num) # BEFORE aggregation 2. trim_ids = trust_mgr.get_trim_ids(valid_ids, round_num) # BEFORE aggregation (trim_ids are excluded from kept_updates) 3. aggregated = defense.aggregate(kept_updates, trust_weights=kept_weights) 4. trust_mgr.update_scores(client_ids, updates, aggregated_update, ...) # AFTER aggregation
🌡 Warm-Up Phase (Rounds 0–4) — 5 Rounds

For the first 5 rounds, trust scoring is INACTIVE. All clients receive uniform weights (plain FedAvg). Scores are observed and accumulated in history but not applied. Warm-up guard ensures round-1 loss deltas (which are pure noise) cannot prematurely tank honest clients. Trust-gated trimming is also disabled during warm-up.

① Cosine Similarity Score
Base metric — all scoring modes

Measures angular alignment of client update Δᵢ with the aggregated reference Δ_agg. Poisoned updates typically point in a divergent direction, producing low or negative cosine similarity.

cos_sim = dot(Δᵢ, Δ_agg) / (‖Δᵢ‖ · ‖Δ_agg‖) cos_score = (cos_sim + 1) / 2 ∈ [0,1] # 0 = opposite direction (bad) # 1 = perfectly aligned (good)
② Blended Norm-Ratio Penalty [v4 FIX]
Self-referential norm baseline

Old method compared a client’s norm only to the current round’s cross-client median. Under non-IID splits, honest clients’ norms legitimately vary round-to-round. Fix: blend each client’s OWN historical norm as a second reference via SELF_NORM_BLEND=0.5.

cross = ‖Δᵢ‖ / median(‖Δ_all‖) self = ‖Δᵢ‖ / median(hist_normsᵢ) ratio = 0.5·self + 0.5·cross norm_score = exp−((ratio−1)² / 0.5) cosine_raw = (1−NORM_PEN)·cos + NORM_PEN·norm [NORM_PENALTY = 0.5]
③ Loss-Delta Score
Stratified rotating validation set

Temporarily applies each client update to the global model and measures validation loss change. Uses a stratified pool (up to 3 batches/class) with rotating k=5 batches per round (seeded by round_num). Concentrated per-class loss spikes trigger an extra 50% penalty.

δ = (loss_after − loss_before) / max(loss_before, 1e-8) if δ ≤ 0: score += 5% (recovery bonus) else: loss_raw = exp(−10·δ) if concentrated_class_spike: × 0.5 (fraction_spiked ≤ 0.25 AND spike > 0.3)
④ Sign Consistency Gate [OptiGradTrust F.2]
Universal gate applied to ALL modes

Computes the fraction of gradient dimensions whose sign matches the element-wise median reference (more robust than using aggregated update). Label-flipping attackers invert gradient directions on targeted features even when cosine similarity remains moderate.

reference = torch.median(stack(Δ_all), dim=0) mask = |reference| > 1e-9 (non-trivial dims) sign_score = mean(sign(Δᵢ[mask]) == sign(ref[mask])) ∈ [0,1] gate = 0.5 + 0.5·sign_score ∈ [0.5, 1.0] raw_score *= gate # applied BEFORE sharpening
⑤ Score Sharpening [v4 FIX]
Widens honest/suspicious separation

Under mild attacks, raw scores cluster in a narrow 0.86–0.996 band — barely down-weighting anyone after normalisation. A monotonic exponent (> 1) applied post sign-gate widens the gap without re-ranking anyone (monotone transform).

raw_score = raw_score ^ SHARPEN_EXPONENT SHARPEN_EXPONENT = 2.5 Examples: 0.990 → 0.975 (honest, barely changed) 0.850 → 0.614 (suspicious, pushed down) 0.500 → 0.177 (adversarial, heavy penalty) 0.300 → 0.027 (strong attacker, near-zero)
⑥ Variance-Aware Adaptive Alpha [OptiGradTrust F.5]
Sleeper attacker detection — non-IID safe

If a client’s score drops anomalously relative to their own history (personalised σ-threshold), alpha is boosted so the EMA penalty lands fast. Honest non-IID clients with naturally high variance are protected by the personalised sigma calculation.

hist_std = std(client_history) (last WINDOW rounds) threshold = max(0.25, 2.0 × hist_std) drop = hist_mean − raw_score if drop > threshold: ema_alpha = 0.60 (BOOST_ALPHA — react fast) else: ema_alpha = 0.20 (base alpha — normal EMA) # Warm-up: always use base_alpha = 0.20
⑦ EMA Trust Accumulation
Temporal smoothing over history

Trust is EMA-smoothed across rounds using the (possibly boosted) adaptive alpha. Consistent attackers accumulate penalties; a single noisy round cannot permanently damage an honest client. Floor TRUST_MIN=0.1 ensures no client is fully silenced. Absent clients decay toward TRUST_MIN.

new_score = (1−α)·old_score + α·raw_score new_score = clamp(new_score, 0.10, 1.00) history.append(new_score) (maxlen=TRUST_WINDOW=5) # Absent this round (not in client_ids): decayed = (1−α)·old + α·TRUST_MIN
⑧ Trust-Gated Trimming [v4 REPLACEMENT]
Replaces unconditional norm-rank backstop

Old backstop discarded 6/10 clients every round unconditionally by norm rank. New version only excludes a client when its EMA score is a statistically significant outlier relative to the round cohort. Never trims during warm-up; never trims > 40% of cohort; trims nobody when the group looks homogeneous.

z = (mean_score − client_score) / std_score gap = mean_score − client_score candidate if: z > TRIM_Z_THRESHOLD (1.25) [relative outlier] AND gap > TRIM_MIN_GAP (0.05) [absolute outlier] cap = floor(0.4 × num_clients) [40% safety cap] disabled during warm-up rounds (0–4)
🔗 Combined Mode (Experiments 12–14) — Geometric Mean Forces Dual Evasion

Takes the geometric mean of cosine-based and loss-based scores, forcing an attacker to simultaneously evade both checks. A poisoner who generates a plausible gradient direction but still harms validation loss will be caught by the loss arm even if the cosine arm is fooled.

raw_score = sqrt(cosine_raw × loss_raw) # geometric mean raw_score = raw_score × (0.5 + 0.5 × sign_score) # sign gate raw_score = raw_score ^ 2.5 # sharpening new_score = (1−α) × old + α × raw_score # EMA
⚖ get_weights() — Normalised Trust Weights for Aggregation

After scoring, normalised trust weights are returned for use in the aggregator. During warm-up, uniform weights are returned. Low-trust clients contribute proportionally less to the global update.

raw = [scores[cid] for cid in client_ids] total = sum(raw) weights = [r / total for r in raw] # uniform during warm-up (round < 5)

Phase 6 • defenses.py
Trust-Weighted Aggregation
FedAvg / Multi-Krum / Manhattan Distance — all optionally trust-weighted and protected by OptiGradTrust v4
▾
📊 FedAvg + Trust Weights (Default)

Standard weighted average. Trust weights blended with dataset-size weights. Trimmed clients (from get_trim_ids) are excluded before aggregation. Most experiments use this mode combined with OptiGradTrust v4.

combinedᵢ = base_weightᵢ × trustᵢ wᵢ = combinedᵢ / ∑ combined⸙ Δ_global = ∑ wᵢ · Δᵢ
🎯 Multi-Krum (Byzantine Resilient)

Selects m=5 updates with lowest sum-of-squared-distances to nearest (n−f−2) neighbours. Trust modifiers multiply Krum scores for low-trust clients, making them less likely to be selected as good representatives.

krum_scoreᵢ = ∑⸙∈NN dist²(Δᵢ,Δ⸙) × (2 − trustᵢ) [modifier] select m=5 updates with min krum_score final = mean(selected m updates)
📏 Manhattan Distance Defense

Computes L1 distance of each update from the median. Updates beyond median + k·std are down-weighted or excluded. Trust scores additionally scale each client’s contribution to the final weighted average.

l1_distᵢ = ‖Δᵢ − median(Δ_all)‖₁ threshold = median_dist + 2.0 × std_dist effective_wᵢ = trustᵢ × (1 if within else 0)

Security Properties & Guarantees
🔐 Confidentiality

ML-KEM-768 key encapsulation + AES-256-GCM. Model updates are never transmitted in plaintext. Session keys are ephemeral per round — forward secret. HKDF ensures key material is cryptographically strong.

✅ Integrity

AES-GCM authentication tag covers ciphertext + AAD. Any bit-flip, metadata swap, or ciphertext reuse is detected with overwhelming probability. Update is rejected on any tamper event.

🔚 Authenticity

ML-DSA-65 (Dilithium-3) lattice signature over the full bound payload. Quantum-immune — no ECC or RSA. Prevents impersonation: an attacker cannot forge a valid signature without the client’s secret key.

🔄 Anti-Replay

Bound message includes client_id ‖ round_num. Replaying a previous round’s packet fails both signature verification and GCM tag check. AAD also binds each ciphertext to its specific client and round.

🛡 Byzantine Resilience

OptiGradTrust v4 combines 8 mechanisms to detect and down-weight poisoned updates. Combined mode forces attackers to simultaneously evade cosine, loss, sign-consistency checks. Score sharpening widens separation between honest and suspicious clients.

🌎 Quantum Resistance

ML-KEM (MLWE-based KEM) and ML-DSA (MLWE/MSIS-based DSA) are NIST PQC standard algorithms (FIPS 203/204). Immune to Shor’s algorithm. Provides 128-bit post-quantum security level. Implemented via liboqs (Open Quantum Safe project).
